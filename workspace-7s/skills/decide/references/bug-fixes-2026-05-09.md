# Bug Fixes — 2026-05-09

## Bug 1: `None` passed as subprocess argument in `cmd_decide`

**File**: `skills/decide/scripts/decide.py`  
**Function**: `cmd_decide()` (line 82–95)

**Symptom**: `TypeError: expected str, bytes or os.PathLike object, not NoneType` from subprocess.

**Root cause**: `snapshot_date = args.date or None` evaluates to `None` when `--date` is not provided. The `subprocess.run()` command list then contains `"--date", None`, which Python's subprocess module rejects.

**Change 1** — Default date value:
```diff
# Line 82-ish, inside cmd_decide():
-    snapshot_date = args.date or None  # Position.load handles None → latest
+    snapshot_date = args.date or date.today().isoformat()
```

Change rationale: when user runs `decide --plan cn_hb` without `--date`, stake.py internally uses `date.today()` for the computation. The orchestrator only needed this for the output filename — so use today's date here too, which makes the filename `2026-05-09_cn_hb_decide.md` instead of `None_cn_hb_decide.md`.

**Change 2** — Stop passing None to subprocess:
```diff
# Lines 88–95, the subprocess cmd construction:
     cmd = [
         sys.executable, str(stake_script),
         "--plan", plan_id,
         "--version", str(version),
-        "--date", snapshot_date,
         "--format", "json",
         "--output", tmp_path,
     ]
+    if snapshot_date is not None:
+        cmd.extend(["--date", snapshot_date])
```

Change rationale: defensive guard. Even though `snapshot_date` now defaults to a string, the guard ensures the subprocess never receives None even if the code path changes in the future.

## Bug 2: Undefined variable `snapshot_date_str` in `stake.py`

**File**: `skills/decide/scripts/stake.py`  
**Function**: `main()` (lines ~80–110)

**Symptom**: `NameError: name 'snapshot_date_str' is not defined` at runtime.

**Root cause**: The function `main()` constructs the result dict at line 110 with key `"snapshot_date": snapshot_date_str`, but the variable `snapshot_date_str` was never defined anywhere in the function. It was likely intended to be `snapshot_date.isoformat()`.

**Fix** — Add the missing variable:
```diff
# Inside main(), right after snapshot_date is assigned:
     if args.date is None:
         snapshot_date = date.today()
     else:
         snapshot_date = datetime.strptime(args.date, "%Y-%m-%d").date()
+    snapshot_date_str = snapshot_date.isoformat()
```

Change rationale: single-line additive fix. No other code references changed. The new variable is used exactly where the old (undefined) one was referenced: `result = { ..., "snapshot_date": snapshot_date_str, ... }`.

## Bug 3: Feishu `.env` path resolution off by one level in `_push_to_feishu`

**File**: `skills/decide/scripts/decide.py`  
**Function**: `_push_to_feishu()` (lines ~165–175)

**Symptom**: `SEVENS_FEISHU_CHAT_ID not set — Feishu push cannot proceed` even though the variable exists in `./.env`.

**Root cause**: The function recomputes `WORKSPACE_ROOT` from scratch instead of using the already-correct module-level variable. It computes `_SCRIPT_DIR = Path(__file__).resolve().parent` (the `scripts/` directory), then walks up `parents[3]` — but `parents[0]` is already one level up from the file, making the final result one level too shallow.

```
Path resolution comparison:

Module-level WORKSPACE_ROOT (correct):
    Path(__file__).resolve()         = .../decide.py
    .parents[0]                      = .../scripts/
    .parents[1]                      = .../decide/
    .parents[2]                      = .../skills/
    .parents[3]                      = .../workspace-7s/    ✓

_push_to_feishu's WORKSPACE_ROOT (wrong):
    Path(__file__).resolve().parent  = .../scripts/         (already one up)
    .parents[0]                      = .../decide/
    .parents[1]                      = .../skills/
    .parents[2]                      = .../workspace-7s/
    .parents[3]                      = .../.openclaw/       ✗ off by one!

Result: _ENV_PATH = /root/.openclaw/.env   ← wrong, doesn't exist
                vs /root/.openclaw/workspace-7s/.env  ← correct
```

**Fix** — Use the module-level `WORKSPACE_ROOT` directly:
```diff
# Inside _push_to_feishu(), remove redundant recomputation:
     try:
         import os
         import shutil
         import subprocess
         import shlex
-        # Load .env so SEVENS_FEISHU_CHAT_ID is available
-        _SCRIPT_DIR = Path(__file__).resolve().parent
-        _WORKSPACE_ROOT = _SCRIPT_DIR.parents[3]
-        _ENV_PATH = _WORKSPACE_ROOT / ".env"
+        # Use module-level WORKSPACE_ROOT (already resolved correctly)
+        _ENV_PATH = WORKSPACE_ROOT / ".env"
         if _ENV_PATH.exists():
             ...
```

Change rationale: the module-level `WORKSPACE_ROOT = Path(__file__).resolve().parents[3]` at line 17 is correct (it's used throughout the file). The `_push_to_feishu` function was the only place re-computing it with an off-by-one error. Removing the redundant computation eliminates the bug entirely.
